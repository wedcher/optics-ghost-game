# Optics Ghost Game

一款以「看見鬼的像，反推出鬼真正在哪裡」為核心的國中光學遊戲。

> **Prototype scope ≠ Product scope.**
>
> 目前任何單一原型（例如凹透鏡原型）都只是用來驗證完整遊戲的一部分，**不是專案終點，也不得把專案重新定義成單一光學元件的小遊戲**。

## 最終目標

玩家無法直接用肉眼看見鬼。玩家必須利用不同光學元件觀察鬼形成的像，根據光學規律推回鬼的真實位置，再在地板格子上展開封印法陣。

完整遊戲目前至少包含三套核心玩法：

1. **平面鏡**：由鏡中虛像與對稱關係推回鬼的位置。
2. **凸透鏡**：先得到倒立實像，再用主光線的可逆性反推物體位置。
3. **凹透鏡**：在探索視角中觀察正立縮小虛像，標記像的位置，再切換到側視分析模式，用主光線與虛線延長線反推真實位置。

目前**不加入凹面鏡**。

## 核心循環

**發現異象 → 使用光學元件觀測 → 分析像的位置與光路 → 推算真實位置 → 選地板格子 → 展開法陣 → 顯形／封印**

錯誤封印時，鬼不能直接現身洩漏答案；只允許非常短、方向性不明的嘲笑聲或非定位式回饋。

## 設計原則

- 這不是「選擇題包遊戲皮」，而是讓光學現象本身成為玩法。
- 難度主要來自**移除鷹架**，不是縮小格子或提高觸控精度。
- 手機觸控優先；學生可能直接用手指操作。
- 學生端以瀏覽器即可執行為優先，避免安裝。
- 優先採固定場景背景 + 動態光學／互動圖層，不追求不必要的完整 3D。
- 光學物理必須正確；若視覺效果與物理衝突，優先修正物理。
- 新 AI 進入專案時，必須先讀 `GAME_SPEC.md`、`PROJECT.md`、`docs/decisions.md`、`docs/visual-handoff.md`。

## 目前階段

目前處於 **玩法與物理原型驗證階段**。

第一個高風險原型：**凹透鏡**。

原因不是它最重要，而是它目前最需要驗證：
- 探索視角中的凹透鏡畫面是否直覺。
- 「標記虛像 → 切換 90° 側視 → 畫光線 → 找真實位置」是否真的能讓學生理解。
- 手機上的縮放、吸附、畫線與選格是否順手。
- 幾何是否能穩定落在唯一答案格。

凹透鏡原型通過後，立即驗證凸透鏡與平面鏡，最後再整合美術、關卡進程與完整遊戲流程。
