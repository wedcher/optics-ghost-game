## 做了什麼

- **流程**（使用者 2026-11-17 定案）：開場過場 → 兩面鏡抓 2 次 → 過場「鬼打碎右邊的鏡子」→ 只剩正面鏡再抓 3 次 → 過關演出 →【前往第二關】。同一隻鬼；抓對才換位置；抓錯扣一顆心、鬼不動；3 條命整關共用（打碎鏡子不補命）；命用完 → 失敗畫面 → 重新挑戰（從兩面鏡重來）。
- **畫面**：背景圖只留牆、鏡框、壁燈、窗、天花板。**地板與兩面鏡的鏡中畫面都由程式畫**（使用者 2026-11-17 的想法：把鏡子與地板「挖空」）。
  - 相機參數是對著背景圖量出來的（消失點、牆腳線、牆角），程式畫的地板和原圖的牆腳、鏡框對得上，誤差在幾個像素內。
  - 鏡中畫面不是貼圖：把整個房間對鏡面鏡射後，透過鏡面範圍再畫一次。鏡中有地板格、牆、門、窗、玩家自己的剪影、鬼的像；鏡中鏡畫到第二層。
- **操作**：點地板選格（黃框）→「展開封印法陣」。點鏡子裡的像只會提醒「那是像」，不扣命（使用者同意）。左上角有＋／－／全圖，放大後可拖曳平移。
- **過場**用共用的 `prototype/shared/story-scene.js`，沒有改它。
- **不畫輔助線**（`GAME_SPEC.md` 5.3）。

## ISSUES（發現的問題與我做的決定，請使用者看）

> **2026-11-17 換背景圖之後**：下面 ISSUE 1～4、9 講的是第一版背景圖（`Mirror1.png`／`Mirror2.png`，有下框的掛鏡、玩家站得遠）。現在用的是落地鏡的 `Mirror4.png`／`Mirror5.png`，這幾點的現況見文末「追加：換成落地鏡的背景圖」。ISSUE 5～8、10～13 仍然適用。

### 物理與背景圖

1. **原圖的鏡子下緣離地約 0.25 格，這會讓玩法做不起來，所以我把鏡面畫到地板。**
   玩家離正面牆約 8.2 格。鏡子下緣只要離地 0.25 格，鏡後最近的 **2.2 格**地板就會被下框擋住、看不到，學生沒辦法從鏡子底邊開始數格子。這正是原本定案「鏡子由地板延伸到天花板」的原因。
   做法：程式把鏡面一路畫到地板（蓋掉原圖的下框與踢腳板），鏡子底邊畫一條金線當作數格子的基準。原圖下框兩端的角花還留著。
   → 先前我建議「接受有框掛鏡」，那個建議要收回一半：框可以留，但**鏡子一定要落地**。之後若重畫背景，請畫成落地鏡、沒有下框。

2. **以這張背景圖的視角，右邊的鏡子能照到鬼的範圍很小。**
   玩家站得遠、右鏡在側牆靠裡面，從玩家的位置透過右鏡只看得到右後方角落附近。結果：
   - 兩面鏡都看得到整隻鬼的只有 1 格（c3r1）；兩面都看得到腳、身體、頭的再加 1 格（c4r3）。
   - 所以雙鏡階段的出題格定成「一面鏡看得到腳身頭、另一面至少露一部分」，共 6 格：c3r1、c4r1、c3r2、c4r2、c4r3、c4r4。
   - 單鏡階段 10 格：第 2、3 欄的四排，加上 c4r3、c4r4。
   - **最左邊那一欄（第 1 欄）兩面鏡都照不到，永遠不會出題。** 學生玩久了可能會發現。
   這是幾何算出來的，不是程式的限制；要改善只能換背景圖的視角（玩家站近一點、或右鏡往玩家這邊移）。

3. **鏡子裡的格子很小。** 正面鏡裡相鄰兩排的像，腳的位置在手機橫向畫面上只差約 **7 CSS px**（c2r3 與 c2r4）。原因同上：玩家離鏡子遠。
   已做的補救：地板改成兩種深淺交錯（棋盤），比較好數；加了＋／－／全圖按鈕，放大 2.5 倍後差 18 CSS px。
   **手機上到底數不數得出來，要真人試。** 這是這一關目前最大的風險。

4. **地板最遠那一排在手機上只有約 14 CSS px 高**（各排由遠到近 14、18、25、37）。點格子中央選得到（測過），而且選了之後要再按一次「展開封印法陣」才生效，點錯可以改；但 14 px 遠小於一般建議的 44 px。放大後是 35 px。同樣要真人試。

5. **選格的黃框與法陣不會出現在鏡子裡。**（我自己決定的，請確認）
   法陣是場景裡發光的東西，照物理應該照得出來。但如果鏡子裡看得到黃框或法陣，學生只要一格一格點，看鏡中的黃框有沒有和鬼的像疊在一起，就能不靠推理對出答案；抓錯時鏡中的法陣和鬼像的相對位置也等於洩漏方向。所以定成「選格標示是介面，不是場景」「法陣鏡子照不出來」。
   抓對之後現身的鬼是場景裡的東西，鏡中的像照常存在。

6. **鬼的像在正面鏡裡看起來沒有左右相反，在右邊的鏡裡才相反。**
   程式把鬼當成一片平行正面牆的半透明人形，照幾何去鏡射。平面鏡其實是前後相反，不是左右相反：一片正對著鏡子的半透明圖案，鏡中看起來和直接看是同一個方向；側面那面鏡才會把牠的左右對調。這在物理上是對的，但學生（和老師）常說「鏡子左右相反」，可能會覺得奇怪。要不要調整鬼的朝向（例如讓鬼面向玩家）等使用者決定。

7. **正面鏡裡有玩家自己的剪影**（小小的深色人形，在門前面）。玩家正對著鏡子，照理看得到自己，所以畫了。牠在鬼的像後面，不會擋到。不想要的話可以拿掉。

8. **鏡中鏡會出現第二個像。** 兩面鏡互相照得到：例如右邊的鏡子裡看得到正面鏡，正面鏡裡又有一隻鬼。物理上是對的（畫到第二層），但畫面上會多出鬼像，學生可能搞混。等真人試了再決定要不要只留第一層。

9. **單鏡階段右鏡的下框又出現了。** 雙鏡階段右鏡被程式畫到落地；鏡子碎了之後直接用 `Mirror2.png` 畫的碎鏡（有下框）。碎鏡裡畫死的反射用半透明黑壓暗了。視覺上小小不一致。

10. **程式畫的地板沒有原圖的質感**（石紋、燈光倒影）；碎玻璃改由程式畫小三角形。等地磚貼圖好了再換。鏡中的牆是單色加木板縫，鏡中的門、窗是簡化的色塊。

- 學生看得懂「鏡子裡的地板是房間地板的延伸，像站在鏡後第幾格，鬼就在鏡前第幾格」。完全沒有真人資料。

- 相機參數是我目測量點後算的；程式畫的地板和原圖牆腳「看起來」對得上，但原圖是 AI 畫的，透視本身不完全一致。

## 追加：換成落地鏡的背景圖（2026-11-17）

使用者試玩後說「真的該換成落地鏡，不然好難玩」，請美工 AI 重畫了三張：

- `Mirror3.png`（使用者自己下的提示詞）：仍是有下框的掛鏡、鏡中畫死了反射、只有碎鏡的一張。**沒有用。**
- `Mirror4.png`／`Mirror5.png`（用我給的提示詞）：兩面落地鏡，正面鏡幾乎佔滿整面牆，右鏡從牆角延伸到畫面右緣之外；鏡面是純暗色；兩張除了右鏡打碎以外相同。**現在用這兩張。**

### 做了什麼

- 重新量相機參數（`prototype/plane-mirror/configs.js` 檔頭有量法）：鏡頭正對正面牆、視平線 y=418、f≈1350；房間寬定為 6 格，眼高 1.706 格，離正面牆 7.83 格。算出的牆角、牆腳線、鏡框內緣、圖上地磚格線和圖上量到的位置相差 ≤ 8 px。
- 地板格改為 **6 欄 × 3 排 = 18 格**（第 4 排已超出畫面下緣）。鬼的大小換算成新的格子單位（寬 0.81、高 1.6 格，在畫面上和之前差不多大）。
- 放大時上下以鏡子底邊附近為準（原本以畫面中央為準，放大後地板會跑出畫面）。
- 壁燈、窗、門的位置照新圖調整。碎鏡直接用 `Mirror5.png` 畫的，不用再壓暗。

- **右鏡現在真的有用**：鬼往前後移動一排，右鏡裡的像會左右移動一大段，很好判斷是第幾排；正面鏡則容易看出是第幾欄。兩面鏡互相補足，打碎右鏡後只剩正面鏡、要往鏡子深處數排數，難度才會上去。
- **還在的風險**：單鏡階段，正面鏡裡相鄰兩排的像在手機上仍只差約 10 CSS px（三排的格線在鏡中依序約 13、10、7 CSS px 高）。這是「正對著你的鏡子，前後距離在畫面上被壓扁」的本質，換圖只改善一點。要靠棋盤格、放大鈕，以及只有 3 排。**仍需真人在手機上試。**
- 地板最遠一排在手機上 17 CSS px 高，仍偏小（放大後 43）。
- 新圖的真實地板只佔畫面下方四分之一，所以只有 3 排可點。若之後覺得格子太少，請美工把鏡頭稍微往下帶、讓地板佔畫面下方約四成。
- 開場與過場的背景直接用新圖：鏡面是一片暗色（程式才會畫反射），台詞說「鏡子裡有東西」時鏡子是黑的。之後可以考慮過場用另一張圖。
