## 1. 整體氛圍與美術方向

- 整體是「光學抓鬼／驅魔」的遊戲感。
- 希望有靈異、神秘、法陣、鬼怪的氣氛，但仍要讓學生清楚看懂光學現象。
- 美術不能搶走物理資訊；課堂辨識度優先。
- 正式版會需要較完整的場景、美術、鬼與法陣效果。
- 目前 prototype 不需要精緻美術。
- 可以先使用簡單幾何、色塊、placeholder、奇怪的方塊或圖形代表物件。
- GPT／ChatGPT 之後會負責概念美術與視覺 refinement，因此目前不要把大量時間花在 polish。
- 色調目前沒有正式定案，不要自行把某一種配色視為已確認規格。

## 2. 畫面怎麼做

不打算一開始做完整自由 3D。原因：

- 光學玩法主要需要清楚的空間關係，不需要自由走動。
- 手機操作若加入完整 3D，容易增加不必要的瞄準與操作負擔。
- 開發成本會大幅增加，但未必改善學習玩法。

優先方式：**固定背景圖／固定透視場景**，上面再疊加：

- 鬼的像
- 透鏡
- 鏡面內容
- 光線
- 標記
- 地板格
- 法陣
- 少量動畫

平面鏡與凸透鏡尤其適合「固定背景＋動態圖層」。

凹透鏡探索畫面較特殊：

- 透鏡內的整個場景必須重新映射。
- 不能只把鬼縮小。
- 透鏡內外背景不應完全無縫接續。

## 3. 每個畫面玩家看到什麼、能做什麼

### A. 凹透鏡：探索

玩家看到：

- 大型開放荒野。
- 第一階段沒有地板格子。
- 玩家位於中央，可往四個約 90° 的方向搜尋。
- 鬼本體裸眼不可見。

玩家可以：轉換觀察方向、舉起凹透鏡、放下凹透鏡。

舉起凹透鏡時：

- 透鏡內整個場景應被重新映射／縮小／產生較廣視野。
- 鬼以正立、縮小的虛像出現在透鏡中。
- 不是只有鬼 sprite 縮小、背景保持原樣。

### B. 凹透鏡：標記

玩家找到鬼的虛像後：

- 可以標記「看起來鬼所在的位置」。
- 這個標記代表虛像位置，不是鬼的真實位置。

之後：玩家放下／移除凹透鏡 → 鬼的虛像消失 → 剛才標記的位置保留。

### C. 凹透鏡：側視分析

玩家切換到約 90° 的側視光學分析畫面。這時才顯示：

- 地板格子
- 凹透鏡
- 主光軸
- 光心
- 焦點
- 剛才標記的虛像位置
- 畫光線工具

玩家可以：

- 畫主光線，使用吸附點。
- 畫實線／需要時畫虛線延長線。
- 放大／縮小，放大後平移畫面。
- 根據光路反推出鬼的真實位置。

畫線不要求自由手繪精準直線。

### D. 封印

分析完成後：玩家選擇一個地板格子，在該格展開魔法封印法陣。

- **正確**：鬼被迫顯形，封印成功。
- **錯誤**：法陣亮起但沒有鬼，法陣消退。
  - 不能讓鬼在旁邊出現，否則會直接洩漏真實位置。
  - 可有極短、方向性不明的鬼笑，例如「嘻」。
  - 音效不能變成定位工具。

### E. 凸透鏡

場景方向：

- 長、窄的房間／走廊。
- 鬼在物側。
- 中間是大型凸透鏡。
- 另一端是白色投影牆／屏幕。

玩家：移動凸透鏡 → 讓白牆上出現清楚的倒立鬼實像 → 進入分析模式 → 用主光線反推鬼本體位置 → 選地板格 → 展開法陣。

### F. 平面鏡

場景方向：

- 固定透視房間，地面有格子。
- 初期有兩面互相垂直、從地板延伸到天花板的鏡子。
- 同一隻鬼在兩面鏡中依正確幾何形成虛像。

重點：

- 鏡中的地板反射必須和房間空間一致。
- 看起來應像房間真的延伸到鏡後。
- 不要像牆上貼了兩個螢幕。

玩家：觀察兩面鏡中的鬼像，用對稱／物距等於像距判斷真實格子；不一定需要畫輔助線。

後期：鬼可以打碎其中一面鏡，只剩一個鏡像資訊，難度提高。

## 4. 已畫過的圖

### 平面鏡房間概念圖

用途：表達固定透視房間＋鏡子的方向、以及「發現鬼影 → 顯示格線 → 錯誤示範 → 正確封印」的流程氣氛。

重要修正／重點：

- 鏡子應是接近全高、由地板延伸到天花板。
- 地板格必須自然延續到鏡中反射。
- 鏡子應像真的空間延伸，不是顯示器。

### 第一張凹透鏡手持概念圖（未存入 repo）

玩家拿凹透鏡，鏡片裡看到縮小鬼。但該圖有物理錯誤：只有鬼縮小，地板格／背景在透鏡內外幾乎無縫連續。**不能作為物理參考。** 它反而確認了一個規則：凹透鏡必須改變整個透鏡區域中的場景，不是只縮小鬼。

### 第二張凹透鏡概念圖（未存入 repo）

上半部類似手持凹透鏡觀察，下半部是光學分析示意，用來表達「先看虛像，再切到另一個分析視角」。之後設計改為：大型荒野、探索時沒有地板格、中央四方位搜尋、找到虛像後切 90° 側視。核心概念仍有參考價值，但場景與版面已不是最新定案。

### 凹透鏡荒野背景（三張）

夜晚荒野、石造遺跡拱門、枯樹、遠山、霧與草地。供探索視角背景使用，詳見 `docs/concepts/README.md`。

## 5. 已經決定 vs 還在猶豫

### 已經決定

- 完整產品包含平面鏡、凸透鏡、凹透鏡；暫不加入凹面鏡。
- 鬼裸眼不可見；光學元件讓玩家看到的是像，不是鬼本體。
- 最後要找的是鬼的真實位置。
- 攻擊方式為地板格子的魔法封印法陣。
- 不採完整 XYZ 3D 瞄準。
- 手機操作優先。
- 格子不作為難度來源。
- 凸、凹透鏡可畫輔助光線；平面鏡不強制畫光線。
- 凹透鏡探索時不顯示格子；分析時切 90° 側視。
- 凹透鏡內整個場景要重新映射。
- 平面鏡可由雙鏡逐步變成單鏡。
- 難度主要透過移除鷹架增加。
- prototype 階段先驗證物理與玩法，不先追求正式美術；正式版仍然需要完整美術。

### 還在猶豫／需要 prototype 驗證

- 凹透鏡內場景重映射最好的實作方式。
- 探索視角切 90° 側視後是否足夠直覺。
- 手機上畫線、縮放、平移是否順手。
- 凸透鏡移動到清晰實像這個操作本身是否有趣。
- 平面鏡雙鏡 → 單鏡的難度差是否足夠。
- 正式鬼造型、法陣造型、場景色調、遊戲名稱。
- 三種光學玩法最後各需要多少關。

## 6. 千萬不要這樣做

- 不要把目前的凹透鏡 prototype 當成整款遊戲，或把專案縮成「凹透鏡小遊戲」。
- 不要為了漂亮而犧牲光學正確性。
- 不要在凹透鏡裡只縮小鬼、背景不變。
- 不要讓凹透鏡虛像投影到屏幕上。
- 不要用失敗後鬼直接現身來提示答案。
- 不要用方向性聲音洩漏鬼的位置。
- 不要用超小格子或超精細點擊增加難度。
- 不要要求學生自由手畫完美直線。
- 不要為了統一玩法，強迫平面鏡也使用主光線作圖。
- 不要自己加入凹面鏡。
- 不要在 prototype 階段大量花時間做精緻美術。
- 目前可以放心使用怪幾何、簡單色塊與 placeholder；GPT／ChatGPT 會負責後續美術與視覺 refinement。
