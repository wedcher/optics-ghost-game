# 光學實驗桌模擬器（`bench/`）

學校找不到實驗儀器，所以做一個模擬器。獨立於遊戲本體（不載入 `prototype/` 的任何檔案），之後要搬到新 repo 直接複製 `bench/` 整個資料夾即可。

試玩：`bench/index.html`（手機橫放）。所有數字在 `bench/config.js`，改數字即可，畫面比例自動跟著算。

## 已定案（使用者 2026-11-23）
- 純儀器模擬器，不帶遊戲外殼。第二關＝凸透鏡、第三關＝凹透鏡，兩者同一個程式（上方按鈕切換，f = ±10）。
- 透鏡位置固定；**燈具與光屏的底座可拖曳**（沿光軸），底座旁有一圈加大的觸控範圍。
- 燈具＝三個指尖燈疊成 L 形（藍右上、紅左下、綠右下，從透鏡這側看）。**不做真 3D**：側面圖與正面圖各畫成符合的立體造型。只有燈窗（面向透鏡的圓形窗）發光，成像只算燈窗。
- 物的底部在光軸上，物高 3 cm（每個燈 1.5 cm、長 3 cm）。
- 側面圖與光路分析圖都標出 **F 與 2F（透鏡左右各一組）**。
- 光路分析時燈具不消失。
- **分析光路要像遊戲一樣，由學生自己拖曳畫線**（使用者 2026-11-23：這是最重要的功能）：先「找到像了」→「分析光路」→ 從標示點拖曳。沒有任何自動畫好的光路。

## 預設值（Claude 決定，錯了改 `config.js`）
f = 10 cm（固定）、鏡徑 10 cm、光具座 84 cm、透鏡在 30 cm；L 形燈具高 4 cm（每個燈 2×2×4 cm、燈窗半徑 0.75）；物距 5～26 cm、像距 8～52 cm；光屏 16×18 cm；眼睛在透鏡後 30 cm，近點 10 cm；開場物距 25、光屏在 62 cm（要自己找清楚的位置）。

**版面（使用者 2026-11-23 用圖指定）**：左邊大的側面圖（含按鈕列），右邊由上到下三張小圖：光屏、看透鏡、燈具正面。桌面縮短到 84 cm，是因為左欄變窄，要靠縮短才能維持每公分的像素數；f 不變、透鏡與物體放大，是改相對尺寸，物理沒變。

## 方向約定（`bench/optics.js` 檔頭，測試在 `tests/check-bench.js`）
- 「正面」＝從透鏡這側看燈具。
- 光屏預設也從透鏡這側看：薄透鏡實像**只有上下顛倒、左右沒有反**。課本說的「上下左右都相反」是從光屏**背面**（隔著半透明屏）看，按鈕「光屏：背面看」可切換。
- 看透鏡：像在鏡片裡的位置 = Mv × 燈窗位置，Mv = 1 / (1 + u/d − u/f)；Mv < 0 表示上下左右都反。
- 光屏上光斑中心由通過光心的光線決定；模糊半徑 = 口徑半徑 × |1 − s/f + s/u|。

## 已知限制／下一步
- 側面圖沒有縮放；手機橫放約 7 px／cm。
- 還沒在實體手機驗證；只在 headless Chromium（844×390）測過拖曳與畫面。
- 只有燈窗發光，燈身在暗室裡看不見的部分沒畫進「看透鏡」。

## 分析光路（學生自己畫，做法照遊戲）
- 流程：移動燈具與光屏 →「找到像了」（實像：光屏上要清楚，模糊度 ≤ 0.4 cm 才收；虛像：隔著透鏡要看得到）→「分析光路」。分析時燈具、透鏡、光屏位置鎖住。移動燈具或換透鏡會清掉標記與線。
- 標示點：O、F、F′（凹透鏡時 F 在右、F′ 在左）、物（燈的上端）、像標記，以及學生畫的線與透鏡平面的交點 P。
- 拖曳規則（和遊戲 `convex-lens/app.js` 相同）：從標示點拖出跟手的預覽；碰到另一個點、起點往手指方向的線經過某點、或拉成水平／垂直時吸附並變實線；放開時實線留下、虛線消失。線一律通過兩點、自動向兩邊延長。水平與垂直線綠色，兩點連線黃色。
- 按鈕：復原、清除線、對答案（才會畫出自動算好的三條主光線）、回實驗桌。「示範光路」（實驗桌上自動畫三條主光線）預設關。
- **畫面比例（使用者給的參考圖）**：分析畫面上下方向拉伸 2.5 倍（`config.js` 的 `analysisStretch`），透鏡約 2.5 倍焦距高、物約 1 倍焦距高；軸線白色粗線、F 與 2F 大字、線條粗。上下拉伸不改變光學（直線與交點照樣成立）。**分析畫面的透鏡畫成幾乎撐滿畫面高度**（使用者 2026-11-23：「透鏡大一點、上下高一點」；照課本把透鏡當一整面平面，P 點與「對答案」的光線都不受 10 cm 口徑限制；實驗桌視角仍是真實口徑 10 cm）。像很大時自動縮小以免超出畫面。
- 測試：`tests/e2e-bench.js`（`npm run test:bench`）：拖曳底座、標記、畫三條線，檢查兩條光線的交點 = 標記的像；虛線不留下；復原／清除；凹透鏡標記虛像。
- **還沒做**：兩點「點一下再點一下」連線（遊戲有，這裡只做拖曳）；分析畫面的縮放／平移；過關式的檢查（這是教學模擬器，沒有對錯判定）。

## 2026-11-24 使用者要求（已做）
- **「對答案」**：粗線（5.5 px）、較深的飽和色（紅／紫／橘，和學生畫的黃／綠區分）、發光；按下後光從物的上端「放出」（約 1.4 秒動畫：物上端有光暈，三條光線帶一個光點往前長），長完才顯示像的箭頭。
- **燈具吸附 F、2F**：拖曳經過 F（物距 10）、2F（物距 20）0.7 cm 內會吸住，F／2F 標示亮白框、顯示「燈具吸附在 F」、手機輕震一下。吸附範圍在 `app.js` 的 `SNAP_CM`。
- **光屏左右微調鈕**：光屏上方、半透明的左右三角（跟著光屏），按一下 0.1 cm（`NUDGE_STEP`），按住 0.38 秒後連續移動；微調不會清掉標記。
- **右下角全螢幕鈕**（燈具正面那格的右下角）：點了進全螢幕、圖示變成「縮小」，同位置再點就退出。iPhone Safari 網頁不能全螢幕，按鈕自動隱藏（要靠「加入主畫面」，**目前沒做 manifest**）。進全螢幕後 Android 會鎖橫向。
- **手機直拿自動轉 90°**（`bench/landscape.js`，從遊戲簡化而來、不引用遊戲檔案；順時針，和遊戲一致）；觸控座標一律用 `BenchLandscape.toLocal`。取代原本的「請橫放」遮罩。
- 試玩網址：`raw.githack.com` 是開發測試用的服務，給學生長期用建議改放 GitHub Pages（新 repo 或 main）。
- 按鈕「標記像」改名「找到像了」（使用者 2026-11-24；內部還是標記像的位置）。
- **光屏經過焦點吸附**（使用者 2026-11-24）：拖曳光屏經過 F（像距 10）、2F（像距 20）0.7 cm 內吸住，標示亮白框、輕震；**微調鈕不吸附**（才能細調到像清楚）。
- **iPhone（使用者 2026-11-24：「你做 iPhone 的」）**：iPhone Safari 網頁不能全螢幕，所以：①右下角按鈕在 iPhone 變成「分享」圖示，點了出現說明卡（分享 → 加入主畫面 → 從圖示開啟）；②加了 `manifest.webmanifest`、`apple-touch-icon`、`apple-mobile-web-app-capable`（狀態列 `black`，內容不會被狀態列蓋住），從主畫面開啟時沒有網址列，這時按鈕自動隱藏；③圖示 `bench/assets/icon-180／192／512.png` 是這個模擬器自己的（L 形燈具、凸透鏡、光線、像），不是遊戲的圖。**只用 UA 模擬在 headless Chromium 測過，還沒在真的 iPhone 驗證**（尤其主畫面開啟後的直拿轉向、狀態列）。
